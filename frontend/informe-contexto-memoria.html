¿La aplicación recuerda el contexto de la conversación?

📝 Respuesta Rápida

✅ MODO TEXTO: SÍ mantiene contexto completo y persistente
⚠️ MODO VOZ: Mantiene contexto DENTRO de la sesión, pero NO entre sesiones
❌ TEXTO y VOZ NO comparten contexto entre sí

💬 Modo TEXTO (Chat)

✅ MEMORIA PERSISTENTE Y COMPLETA

¿Cómo funciona?

🔍 Implementación de Threads Persistentes

# Diccionario que mantiene threads por usuario self.user_threads: Dict[str, str] = {} # {user_id: thread_id} async def connect(self, websocket: WebSocket, user_id: str): # Si ya tiene un thread, recuperarlo; sino, crear uno nuevo if user_id in self.user_threads: thread_id = self.user_threads[user_id] logger.info(f"📂 Sesión recuperada: {user_id}") else: client = self._get_client() with client: thread = client.agents.create_thread() # Crea nuevo thread en Azure thread_id = thread.id self.user_threads[user_id] = thread_id logger.info(f"🆕 Nueva sesión: {user_id}") return thread_id

Características de la memoria en modo texto:

  • ✅ Persistente: El historial se guarda en Azure AI y permanece aunque cierres el navegador
  • ✅ Por usuario: Cada usuario tiene su propio thread independiente
  • ✅ Recuperable: Si te desconectas y vuelves con el mismo user_id, recuperas tu historial completo
  • ✅ Ilimitado: No hay límite aparente de mensajes (depende de Azure AI)
  • ✅ Incluye todo: Todas tus preguntas y respuestas del agente
💡 Ejemplo de uso
Sesión 1 (Lunes):

Usuario: "¿Qué es Sikalastic-560?"

Bot: "Es una membrana líquida impermeabilizante..."

Usuario cierra el navegador y se va a casa...
Sesión 2 (Martes, desde otro dispositivo):

Usuario: "¿Cuánto tiempo tarda en secar?"

Bot: "El Sikalastic-560 que mencionaste ayer tarda aproximadamente..." (El bot recuerda la conversación anterior)

🎤 Modo VOZ

⚠️ MEMORIA TEMPORAL (solo durante la sesión)

¿Cómo funciona?

🔍 Azure Voice Live API

backend/voice/voice_manager.py:231-361

El modo voz utiliza Azure Voice Live API, que es diferente a la API de chat con threads.

def start(self) -> str: # Conectar a Voice Live API self.connection = client.connect( agent_connection_string=agent_connection_string, agent_id=self.agent_id, # ← Mismo agente que texto agent_access_token=agent_token.token ) # Configurar sesión de voz (NO hay thread_id aquí) session_update = { "type": "session.update", "session": { "turn_detection": { ... }, "voice": { ... } } }

Características de la memoria en modo voz:

  • ✅ Mantiene contexto DENTRO de la sesión: Mientras el micrófono esté activo, recuerda la conversación
  • ❌ NO es persistente: Cuando desactivas el modo voz, se pierde el contexto
  • ❌ NO crea threads: No usa el sistema de threads de Azure AI
  • ❌ NO recuperable: Si te desconectas, no puedes recuperar el historial de voz
  • ⚠️ Temporal: Solo existe mientras la sesión de voz está activa
⚠️ Limitación Importante
Escenario:

Usuario activa voz: "¿Qué es Sikalastic-560?"

Bot responde: "Es una membrana líquida..."

Usuario pregunta: "¿Cuánto tiempo tarda en secar?"

Bot: "El Sikalastic-560 tarda aproximadamente..." ✅ (Recuerda porque estás en la misma sesión)

Usuario desactiva el modo voz (presiona botón de micrófono)

Usuario vuelve a activar el modo voz

Usuario pregunta: "¿Y cuál es su precio?"

Bot: "¿El precio de qué producto?" ❌ (NO recuerda la conversación anterior)

¿Por qué funciona así?

Azure Voice Live API está diseñada para conversaciones en tiempo real, no para persistencia. Es como una llamada telefónica: mientras la llamada está activa, hay contexto, pero cuando cuelgas, se pierde.

🚧 Problema: Los Modos NO Comparten Contexto

❌ TEXTO y VOZ son conversaciones completamente separadas
⚠️ Escenario Problemático
Por TEXTO:

Usuario: "¿Qué es Sikalastic-560?"

Bot: "Es una membrana líquida impermeabilizante..."

Usuario: "¿Cuáles son sus ventajas?"

Bot: "Las ventajas del Sikalastic-560 son..."

Usuario cambia a VOZ:

Usuario (por voz): "¿Y cuál es su precio?"

Bot: "¿El precio de qué producto?" ❌

El bot NO recuerda que estabas hablando de Sikalastic-560 en el chat de texto.

¿Por qué pasa esto?

  • El modo TEXTO usa thread_id de Azure AI Projects
  • El modo VOZ usa session_id de Azure Voice Live
  • Son APIs completamente diferentes
  • No hay sincronización entre ellas

¿Es esto un problema?

Depende del caso de uso:

  • ✅ Si los usuarios usan UN solo modo: No hay problema
  • ❌ Si los usuarios cambian entre modos: La experiencia es confusa y fragmentada
  • ❌ Si quieres una experiencia unificada: Es un problema serio

💡 Recomendaciones

Opción 1: Mantener el diseño actual (Más simple)

✅ Pros
  • No requiere cambios de código
  • Más simple de mantener
  • Usa las APIs como fueron diseñadas
⚠️ Requerimientos
  • Comunicar claramente al usuario que son modos separados
  • Agregar mensaje en UI: "El historial de texto y voz son independientes"
  • Recomendar usar un solo modo por conversación

Opción 2: Sincronizar contexto (Más complejo)

🔧 Implementación sugerida

Para lograr contexto compartido, necesitarías:

  1. Mantener el thread de texto siempre:
    • El thread de texto es la "fuente de verdad"
    • Persiste todo el historial
  2. Al activar modo voz:
    # Antes de iniciar Voice Live: # 1. Obtener el historial completo del thread de texto messages = client.agents.list_messages(thread_id=user_thread_id) conversation_history = format_messages(messages) # 2. Inyectar contexto en la sesión de voz como "instrucciones" session_update = { "type": "session.update", "session": { "instructions": f"Contexto previo: {conversation_history}", ... } }
  3. Al desactivar modo voz:
    • Transcribir toda la conversación de voz
    • Guardarla como mensajes en el thread de texto
⚠️ Consideraciones
  • Aumenta la complejidad significativamente
  • Puede haber límites de tokens en las instrucciones de Voice Live
  • La sincronización puede fallar
  • Requiere más tiempo de desarrollo y testing

Opción 3: Voice-Only con persistencia (Rediseño)

Si quieres priorizar voz:

  • Eliminar el modo texto o hacerlo completamente secundario
  • Transcribir todas las conversaciones de voz
  • Guardar transcripciones en un thread de texto en background
  • Usar ese thread como fuente de contexto para nuevas sesiones de voz
